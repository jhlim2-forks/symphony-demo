# 요구사항

## 배경

팀원이 브라우저에서 할 일을 적어 두는 간단한 웹앱이 필요합니다. 첫 버전은 할 일 제목을 입력해 추가하고, 추가한 순서대로 목록을 보는 것까지를 다룹니다. 화면은 한 페이지로 충분하고 한국어로 보여 줍니다. 할 일은 서버 메모리에 보관하므로 서버를 다시 켜면 목록은 비어 있는 상태로 시작합니다.

할 일마다 언제까지 해야 하는 일인지를 따로 기억하지 않아도 되도록, 할 일에 날짜만으로 된 마감일을 함께 적어 두고 목록에서 제목과 함께 보는 동작도 다룹니다. 마감일은 적어도 되고 적지 않아도 되는 선택 항목이며, 달력에 없는 날짜는 받지 않습니다.

## 요구사항

- **REQ-01** 서버는 `/` 요청에 할 일 추가 입력과 할 일 목록이 함께 있는 한국어 한 페이지 화면을 보여 준다.
- **REQ-02** 사용자가 할 일 제목을 입력해 추가하면 그 할 일이 목록에 담기고, 서버는 추가된 할 일의 식별자와 제목을 돌려준다.
- **REQ-03** 제목이 비어 있거나 공백 문자만 있으면 추가를 거절하고 목록을 바꾸지 않으며, 한국어 오류 메시지를 돌려준다.
- **REQ-04** 앞뒤 공백을 제거한 제목의 글자 수가 200을 넘으면 추가를 거절하고 목록을 바꾸지 않으며, 한국어 오류 메시지를 돌려준다. 200자까지는 받아들인다. 글자 수는 유니코드 코드 포인트 개수로 센다.
- **REQ-05** 할 일 목록은 추가한 순서대로 보여 준다.
- **REQ-06** 할 일은 서버 메모리에만 보관하므로, 서버를 다시 켜면 목록은 빈 상태에서 시작한다.
- **REQ-07** 할 일이 하나도 없으면 화면의 목록 자리에 안내 문구 `아직 할 일이 없으니 위 입력 칸에서 첫 할 일을 추가해 보세요.`를 보여 준다. 이 문구는 화면에서만 보여 주고 API 응답에는 담지 않는다.
- **REQ-08** 빈 목록 안내 문구는 화면에 있는 할 일 수에 따라서만 보이고 숨는다. 할 일이 하나 이상이면 보여 주지 않고, 추가가 성공해 목록이 비어 있지 않게 되면 화면을 다시 열지 않아도 그 자리에서 문구를 숨기며, 목록이 그대로 비어 있으면 문구를 계속 보여 준다.
- **REQ-09** 화면 맨 아래에 `할 일은 이 서버에만 잠시 보관되며, 서버를 다시 켜면 사라집니다.` 안내를 늘 보여 준다.
- **REQ-10** (구현 예정 #1) 할 일을 추가할 때 날짜만으로 된 마감일(연·월·일, 시각 없음)을 함께 지정할 수 있고, 지정하면 그 할 일의 마감일로 보관하며 서버는 추가된 할 일의 마감일을 함께 돌려준다.
- **REQ-11** (구현 예정 #1) 마감일은 선택 항목이다. 마감일을 지정하지 않아도 할 일을 추가할 수 있고, 그 할 일의 마감일은 없음으로 보관한다.
- **REQ-12** (구현 예정 #1) 마감일을 지정한 경우 `YYYY-MM-DD` 형식의 날짜만 받아들인다. 형식이 다르면 추가를 거절하고 목록을 바꾸지 않으며, 한국어 오류 메시지를 돌려준다.
- **REQ-13** (구현 예정 #1) 형식이 맞아도 달력에 없는 날짜(예: `2026-02-30`, `2026-13-01`, 평년의 `2026-02-29`)면 추가를 거절하고 목록을 바꾸지 않으며, 한국어 오류 메시지를 돌려준다.
- **REQ-14** (구현 예정 #1) 할 일 목록 조회 응답은 할 일마다 마감일을 함께 담는다. 마감일이 없는 할 일은 마감일 값을 없음으로 담는다.
- **REQ-15** (구현 예정 #1) 화면의 목록에서 할 일 제목 옆에 그 할 일의 마감일을 `마감일 2026-10-31` 형태로 보여 주고, 마감일이 없는 할 일에는 마감일을 보여 주지 않는다.
- **REQ-16** (구현 예정 #1) 화면의 추가 영역에 마감일을 고르는 입력 칸을 두고, 비워 둔 채로 추가하면 마감일 없는 할 일로 추가하며, 추가가 성공하면 제목 입력 칸과 함께 마감일 입력 칸도 비운다.

## API 계약

모든 API는 `/api/` 아래에서 JSON으로 주고받습니다. 요청과 응답의 문자 인코딩은 UTF-8이며, 응답 헤더는 `Content-Type: application/json; charset=utf-8`입니다.

### `GET /api/todos` — 할 일 목록 조회

- 요청 본문 없음.
- 응답 `200 OK`

  ```json
  { "todos": [ { "id": 1, "title": "회의 자료 준비", "dueDate": "2026-10-31" }, { "id": 2, "title": "메일 답장", "dueDate": null } ] }
  ```

- `todos`는 추가한 순서대로 담은 배열이며, 할 일이 없으면 빈 배열(`[]`)입니다.
- 할 일 하나는 `id`(1부터 1씩 커지는 정수), `title`(문자열), `dueDate`로 이루어집니다.
- `dueDate`는 마감일이 있으면 `"2026-10-31"`처럼 `YYYY-MM-DD` 형식의 문자열이고, 마감일이 없으면 `null`입니다. `dueDate` 항목은 마감일이 없을 때도 응답에서 빠지지 않습니다.
- 할 일이 없을 때도 응답 형식은 위와 같습니다. 빈 목록 안내 문구는 응답 본문에 담지 않으며, 화면이 `todos`의 길이가 0인지를 보고 직접 보여 줍니다.

### `POST /api/todos` — 할 일 추가

- 요청 본문

  ```json
  { "title": "회의 자료 준비", "dueDate": "2026-10-31" }
  ```

- `dueDate`는 선택 항목입니다. `dueDate` 항목이 없거나, `null`이거나, 빈 문자열(`""`)이면 마감일을 지정하지 않은 것으로 보고 마감일 없는 할 일로 추가합니다.
- `dueDate`를 지정하면 `YYYY-MM-DD` 형식의 날짜 문자열이어야 합니다. 형식 기준은 다음과 같습니다.
  - 전체 길이가 정확히 10자이고, `숫자 4개`-`숫자 2개`-`숫자 2개` 순서이며, 숫자는 ASCII 숫자(`0`~`9`)입니다.
  - 월과 일은 한 자리여도 `0`을 붙여 두 자리로 적습니다. 예: `2026-01-05`는 받아들이고 `2026-1-5`는 받아들이지 않습니다.
  - 시각·시간대·구분 기호가 다른 표기는 받아들이지 않습니다. 예: `2026-10-31T00:00:00Z`, `2026/10/31`, `20261031`, `31-10-2026`, 앞뒤에 공백이 붙은 `" 2026-10-31 "`.
- 형식이 맞는 값은 달력에 실제로 있는 날짜여야 합니다. 월은 `01`~`12`, 일은 그 달에 있는 날짜여야 하며 윤년을 따릅니다. 예: `2024-02-29`는 받아들이고 `2026-02-29`, `2026-02-30`, `2026-04-31`, `2026-00-10`, `2026-10-00`은 받아들이지 않습니다. 달력에 없는 날짜를 가까운 날짜로 바꿔 받아들이지 않습니다.
- 받아들인 마감일은 요청에 적힌 `YYYY-MM-DD` 문자열 그대로 보관하고 그대로 돌려줍니다. 시각이나 시간대를 붙이지 않고 다른 형식으로 바꾸지도 않습니다.
- `title`의 앞뒤 공백은 제거한 뒤 저장하며, 길이는 공백을 제거한 제목의 글자 수로 셉니다.
- 글자 수를 세는 기준은 다음과 같습니다.
  - 유니코드 코드 포인트 하나를 1자로 셉니다(Go의 `[]rune` 길이와 같습니다). 바이트 수로 세지 않습니다.
  - 결합 문자나 이모지 조합처럼 화면에 한 글자처럼 보이는 경우에도 코드 포인트마다 1자로 셉니다. 즉 사용자가 눈으로 인식하는 글자 수를 따르지 않습니다.
    - 예: `한`(U+D55C)은 1자, `가`를 `ᄀ`+`ᅡ`(U+1100 U+1161)로 적으면 2자, `é`를 `e`+`◌́`(U+0065 U+0301)로 적으면 2자, `👍🏻`(U+1F44D U+1F3FB)은 2자입니다.
  - 제목 안쪽(앞뒤가 아닌 중간)의 공백은 제거하지 않고 1자로 셉니다.
- 응답 `201 Created`

  ```json
  { "id": 1, "title": "회의 자료 준비", "dueDate": "2026-10-31" }
  ```

  마감일을 지정하지 않았으면 `dueDate`는 `null`입니다.

  ```json
  { "id": 2, "title": "메일 답장", "dueDate": null }
  ```

- 응답 `400 Bad Request` — 아래 경우에 각각 정해진 `error` 문장을 돌려줍니다. 본문 형태는 모두 `{ "error": "..." }` 한 가지입니다.

  | 경우 | `error` 문장 |
  | --- | --- |
  | 본문이 올바른 JSON이 아니거나, 본문이 비어 있거나, `title`이 문자열이 아닌 경우 | `요청 형식이 올바르지 않습니다.` |
  | `title`이 없거나, 비었거나, 공백 문자만 있는 경우 | `제목을 입력해 주세요.` |
  | 공백을 제거한 제목이 200자를 넘는 경우 | `제목은 200자까지 입력할 수 있습니다.` |
  | `dueDate`가 문자열도 `null`도 아닌 경우(예: `{ "dueDate": 20261031 }`) | `요청 형식이 올바르지 않습니다.` |
  | `dueDate`가 `YYYY-MM-DD` 형식이 아닌 경우 | `마감일은 YYYY-MM-DD 형식으로 입력해 주세요.` |
  | `dueDate`가 형식은 맞지만 달력에 없는 날짜인 경우 | `달력에 없는 날짜입니다. 다시 확인해 주세요.` |

  ```json
  { "error": "요청 형식이 올바르지 않습니다." }
  ```

- 여러 경우에 함께 해당하면 위 표의 순서대로 먼저 걸리는 문장 하나만 돌려줍니다.
- `error`는 화면에 그대로 보여 줄 수 있는 한국어 문장입니다.

### 공통

- 위에 적지 않은 메서드로 `/api/todos`를 호출하면 `405 Method Not Allowed`와 `{ "error": "지원하지 않는 요청 방식입니다." }`를 돌려줍니다.

## 범위 밖

- 완료 표시, 할 일 수정, 할 일 삭제
- 로그인과 사용자 구분, 여러 사용자가 각자의 목록을 갖는 기능
- 데이터베이스 등 서버를 다시 켜도 목록이 남는 저장 방식
- 목록 정렬 변경, 검색, 분류, 페이지 나누기
- 화면 디자인 전반 변경(배치, 색, 글꼴 등)
- 할 일 추가와 목록 조회에서, 위 요구사항과 API 계약에 적은 마감일 관련 동작 밖의 동작 및 API 응답 형식 변경
- 빈 목록 안내 문구를 서버 응답에 담아 내려 주는 방식, 문구의 다국어 지원이나 사용자별 변경
- 마감일이 지난 할 일을 따로 표시하거나 색을 달리하거나 알림을 보내는 기능
- 마감일 순으로 목록을 정렬하는 기능, 마감일로 걸러 보거나 검색하는 기능
- 추가한 뒤 마감일을 고치거나 지우는 기능
- 마감일에 시각(시·분)이나 시간대를 넣는 것, 반복 일정, 기간(시작일~종료일) 지정
- 마감일을 `2026년 10월 31일`처럼 다른 형식으로 바꿔 보여 주거나 사용자의 지역 설정에 맞춰 표시하는 것
- 마감일로 받아들일 수 있는 연도 범위를 좁히는 것(예: 과거 날짜 금지)
